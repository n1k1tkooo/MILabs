## 3. Детальное описание ключевых исправлений

### 3.1. Защита от Prompt Injection и утечек 152-ФЗ (LLM01 / LLM02)
* **Проблема:** Злоумышленник мог составить изощренный промпт, чтобы заставить LLM процитировать закрытые документы, содержащие персональные данные или матрицы окладов топ-менеджмента.
* **Реализованное исправление в `server.py`:**
```python
# Защита коммерческой тайны и 152-ФЗ на уровне API Middleware
if any(k in q_lower for k in ["зарплат", "компенсац", "директор"]):
    if user_role == "user":
        log_event("WARN", "RBAC_152FZ_BLOCKED", {
            "user_role": user_role,
            "query": query,
            "reason": "152-FZ / Confidential salary data restriction"
        })
        self._send_json(200, {
            "answer": "Внимание! Запрашиваемая информация относится к категории «Коммерческая тайна / Персональные данные» (152-ФЗ РФ). Доступ для роли 'user' ограничен.",
            "citations": [],
            "is_confidential_warning": True,
            "model_used": model
        })
        return
```

### 3.2. Защита OAuth2 Flow от CSRF атак (A07)
* **Проблема:** Если при редиректе на Яндекс ID не передавать случайный одноразовый токен `state`, злоумышленник может связать аккаунт жертвы со своей учетной записью.
* **Реализованное исправление:**
  * На бэкенде генерируется криптостойкий `state_nonce = str(uuid.uuid4())`;
  * Токен передается в query-параметрах провайдеру `https://oauth.yandex.ru/authorize?state=...`;
  * При получении callback проверяется точное совпадение `state` с выданным токеном.

### 3.3. Аудит зависимостей (Dependency Check)
* Проведен анализ через `pip-audit` и `npm audit`:
  * Все используемые библиотеки зафиксированы с точными версиями в `requirements.txt`;
  * В GitHub Actions пайплайн добавлен обязательный шаг `security-audit`, блокирующий мерж pull request при наличии критических CVE.

## 4. Рекомендации по безопасности для закрытого корпоративного контура

1. **Режим On-Premise:** Хранение векторов эмбеддингов только на локальном экземпляре PostgreSQL 16 `pgvector`, без синхронизации с публичными облачными хранилищами;
2. **TLS 1.3:** Обязательное шифрование сетевого трафика внутри контура предприятия;
3. **Ротация секретов:** Регулярная ротация токенов ЮKassa и Client Secret Яндекс ID через корпоративное хранилище (HashiCorp Vault / KMS);
4. **Маскирование ПДн в аналитике:** При передаче событий в Яндекс.Метрику исключать имена, телефоны и email сотрудников, передавая только системные события (`SEARCH_QUERY_SENT`, `DOC_DOWNLOAD`).
