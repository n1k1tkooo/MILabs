# Шаг 1. Анализ требований к проекту и технологический стек

## 1. Описание проекта
**Название:** DocuMind AI  
**Тип продукта:** Защищенная корпоративная база знаний и интеллектуальный ассистент по регламентам компании (Enterprise RAG Platform).  
**Цель:** Предоставление сотрудникам мгновенных и точных ответов на вопросы по внутренним регламентам, приказам и нормативным актам компании со ссылками на первоисточники, с гарантией соблюдения требований Федерального закона № 152-ФЗ «О персональных данных» и режима коммерческой тайны.

---

## 2. Технологический стек проекта
* **Frontend:**
  * Фреймворк: React 18+ (Vite)
  * Язык: TypeScript (Strict mode)
  * Стилизация: Tailwind CSS
  * Иконки и UI: Lucide React, Headless UI / Radix primitives
  * Управление состоянием: Zustand / React Context
  * Сетевой слой: Axios / TanStack Query
* **Backend & AI-инфраструктура:**
  * Серверная среда: Node.js (TypeScript) / Python (FastAPI для AI-пайплайнов)
  * База данных: PostgreSQL с расширением `pgvector`
  * Аутентификация: JWT / Role-Based Access Control (RBAC)
  * AI-модели:
    * Российские облачные решения: **YandexGPT 5 Pro API** (для обработки общедоступных и внутренних регламентов)
    * On-premise / Local контур: **DeepSeek-V3**, **Qwen 2.5 Coder** (через vLLM / Ollama для работы с грифом Confidential)
* **Инструменты контроля качества:**
  * Линтинг и форматирование: ESLint (strict config), Prettier
  * Тестирование: Vitest, React Testing Library

---

## 3. Ключевые требования к стилю кода, архитектуре и стандартам

### 3.1. Архитектурные требования
* **Feature-Sliced Design / Модульная архитектура:** Разделение на слои `features/`, `components/`, `utils/`, `types/`, `services/`.
* **Zero Trust Security:** Любые входящие данные с клиента и внешних API должны валидироваться через схемы (Zod).
* **Принцип единственной ответственности (SRP):** Разделение UI-отображения, бизнес-логики и работы с сетью.

### 3.2. Стандарты TypeScript
* Запрет на использование типа `any`. Использование `unknown` с type guards или дженериков.
* Обязательное описание интерфейсов для всех пропсов компонентов, данных API и состояния.
* Все интерфейсы данных должны иметь JSDoc-комментарии на русском языке.

### 3.3. Безопасность и 152-ФЗ
* Запрет на жесткое кодирование токенов, ключей и секретов в коде (хранение только в `.env.local` и переменных окружения).
* Обязательное маскирование персональных данных (ФИО, телефоны, email) при логировании.
* Логирование сетевых запросов без передачи тела конфиденциальных документов.
