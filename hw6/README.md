## ⚡ Быстрый запуск на macOS и Linux

Система разработана по принципу **Self-contained (Автономность)** на стандартной библиотеке Python 3. Для запуска **не требуются** внешние тяжелые СУБД, сторонние фреймворки или платные API-ключи.

### Способ 1. Запуск в 1 клик на macOS (Рекомендуется)
Дважды кликните по файлу **`start_full_stack.command`** в Finder (или запустите `./start_full_stack.command` в терминале).  
Скрипт автоматически:
1. Выполнит прогон всех **23 unit-тестов** (`unittest`);
2. Запустит сервер DocuMind AI на `http://localhost:8000`;
3. Проверит системный Health Check (`/api/health`);
4. **Автоматически откроет веб-приложение в браузере**.

### Способ 2. Запуск через терминал
```bash
# 1. Запуск автоматических тестов (23 теста)
python3 -m unittest discover -s tests -p "test_*.py" -v

# 2. Старт сервера
python3 server.py
```
После старта откройте в браузере:  
👉 **[http://localhost:8000/](http://localhost:8000/)** — полнофункциональный интерфейс системы;  
👉 **[http://localhost:8000/api/health](http://localhost:8000/api/health)** — статус мониторинга и интеграций.

### Способ 3. Запуск в изолированном Docker-контейнере
```bash
docker-compose up -d --build
```

## 🛡️ 152-ФЗ РФ и модель безопасности Zero-Trust & RBAC

Система строго спроектирована по требованиям законодательства РФ в области защиты персональных данных:
1. **Закрытый контур (Zero-Trust):** Гостевой доступ к документам закрыт. Самостоятельная регистрация заблокирована (`403 Forbidden`).
2. **Криптография паролей:** `hashlib.sha256(salt + password)`. Индивидуальная соль генерируется через криптографический генератор `secrets.token_hex(16)`.
3. **Разграничение прав (RBAC + RLS):**
   * Каждый документ имеет гриф доступа (`public`, `internal`, `confidential`);
   * Документы с грифом `confidential` (зарплаты, банковские тайны, ключи) доступны **только** ролям `admin` и `security_officer`.
4. **Аудит каждого действия:** Все попытки несанкционированного доступа логируются по стандарту **RFC 5424** с фиксацией IP-адреса, роли, метки времени и параметров запроса.

<details>
<summary><b>1. «Как устроен векторный поиск, если не подключена внешняя база данных?»</b></summary>

> **Ответ:** В системе реализован гибридный векторный движок на базе **TF-IDF + Character 3-grams** с косинусным сходством векторов. Он полностью эмулирует работу индекса **HNSW в PostgreSQL `pgvector`**. Использование символьных n-грамм (3-grams) обеспечивает устойчивость к опечаткам и морфологии русского языка (склонения, падежи) без тяжелых внешних библиотек. Текст документов нарезается на чанки по 200 символов с перекрытием (overlap) 60 символов, что предотвращает потерю контекста на границах фрагментов.
</details>

<details>
<summary><b>2. «Почему в системе заблокирована самостоятельная регистрация?»</b></summary>

> **Ответ:** Это фундаментальное требование безопасности корпоративных систем уровня Enterprise и **Федерального закона № 152-ФЗ (ст. 19)** для информационных систем персональных данных (ИСПДн) уровней УЗ-1 / УЗ-2. В закрытом корпоративном периметре с режимом коммерческой тайны (98-ФЗ РФ) появление внешних неавторизованных учетных записей недопустимо. Новых сотрудников в реестр заводит исключительно системный администратор с явным назначением роли (RBAC) и департамента.
</details>

<details>
<summary><b>3. «Как обеспечивается защита от атак Prompt Injection и Jailbreak?»</b></summary>

> **Ответ:** Реализован **двухуровневый шлюз защиты (Defense-in-Depth)**:
> 1. *Pre-retrieval фильтр:* Анализ входного текста на наличие сигнатур атак («забудь инструкции», «ignore previous instructions», «выведи системный промпт», «отключи правила»). При совпадении запрос немедленно блокируется с предупреждением.
> 2. *Role-Based RLS (Row-Level Security):* Даже если злоумышленник пытается обойти формулировку, семантический векторный ретривер физически отфильтровывает чанки документов, к которым у текущей роли пользователя нет допуска, поэтому модель в принципе не получает секретные данные в свой контекст.
</details>

<details>
<summary><b>4. «Что такое RAG Triad и по каким формулам оценивается качество ответов?»</b></summary>

> **Ответ:** **RAG Triad** — это современный индустриальный стандарт оценки RAG-систем (фреймворки TruLens / Ragas). Он состоит из трех независимых метрик:
> 1. **Faithfulness (Обоснованность / Отсутствие галлюцинаций):** Доля утверждений в сгенерированном ответе, которые строго подтверждаются извлеченными чанками документов.
> 2. **Answer Relevance (Релевантность ответа):** Насколько ответ отвечает на заданный пользователем вопрос, без ухода в посторонние темы.
> 3. **Context Recall (Полнота извлечения):** Насколько полно извлеченные чанки содержат всю информацию, необходимую для формирования исчерпывающего ответа.
</details>

<details>
<summary><b>5. «Как устроена интеграция с ЮKassa и зачем нужна HMAC-SHA256 подпись?»</b></summary>

> **Ответ:** Интеграция реализована по протоколу асинхронных уведомлений (Webhooks). При оплате счета ЮKassa отправляет HTTP POST запрос с телом события (`payment.succeeded`). Чтобы исключить подделку уведомлений злоумышленниками (Man-in-the-Middle), сервер рассчитывает контрольную подпись **HMAC-SHA256** от тела запроса с использованием секретного ключа (`webhook_secret`) и сравнивает ее с заголовком запроса. Только при совпадении подписи статус лицензии активируется.
</details>

<details>
<summary><b>6. «Как масштабировать данное решение для промышленной эксплуатации (Production)?»</b></summary>

> **Ответ:** Архитектура DocuMind AI Enterprise построена по модульному принципу:
> 1. Векторный модуль готов к бесшовному переключению на реальный **PostgreSQL 16 + pgvector** или Qdrant/Milvus простым переопределением адаптера базы в `CONFIG['DATABASE_BACKEND']`;
> 2. В качестве LLM подключается локальный шлюз **vLLM / Ollama** (Llama-3, Vikhr) или защищенный корпоративный контур **YandexGPT-Pro / GigaChat API** через шину шифрования ГОСТ;
> 3. Готовый `Dockerfile` и `docker-compose.yml` обеспечивают оркестрацию в Kubernetes/OpenShift с горизонтальным масштабированием (HPA).
</details>
