# Библиотека промпт-шаблонов по методологии RTCF (prompt_templates.md)

В данном документе представлены 5 специализированных шаблонов промптов для типовых задач разработки платформы **DocuMind AI**. Каждый шаблон спроектирован по структуре **RTCF** (*Role — Task — Context — Format*) и содержит практический пример использования.

---

## Шаблон 1: Генерация компонента / функции по описанию

### Структура RTCF:
```markdown
### ROLE
Ты — Senior Frontend Developer, специализирующийся на React 18, TypeScript и Tailwind CSS.

### TASK
Разработай компонент/функцию [НАЗВАНИЕ] с функциональностью:
- [ТРЕБОВАНИЕ 1]
- [ТРЕБОВАНИЕ 2]
- [ТРЕБОВАНИЕ 3]

### CONTEXT
- Проект: DocuMind AI (корпоративная база знаний)
- Стек: React, TypeScript (strict mode, без any), Tailwind CSS, Lucide React
- Входные данные: [ОПИСАНИЕ ВХОДНЫХ ДАННЫХ И ИНТЕРФЕЙСОВ]
- Ограничения: Должна быть поддержка доступности (a11y), адаптивность под мобильные экраны и обработка состояний загрузки/ошибки.

### FORMAT
1. Полный TypeScript-код файла (без пропусков и плейсхолдеров).
2. Порядок секций: импорты -> интерфейс Props -> константы -> компонент -> экспорт.
3. JSDoc-комментарии на русском языке.
```

### Пример использования Шаблона 1:
> **Запрос к агенту:**
> 
> **ROLE:** Ты — Senior Frontend Developer, специализирующийся на React 18, TypeScript и Tailwind CSS.  
> **TASK:** Разработай компонент `DocumentUploadZone` (зона Drag-and-Drop загрузки нормативных документов) со следующей функциональностью:  
> - Перетаскивание файлов (drag over / drop) с визуальной подсветкой рамки;  
> - Фильтрация по типам: только `.pdf`, `.docx`, `.txt`, `.md`;  
> - Валидация размера файла (максимум 20 МБ);  
> - Отображение прогресса загрузки и статуса безопасности (проверка 152-ФЗ).  
> 
> **CONTEXT:** Проект DocuMind AI. Запрещено использовать `any`. Иконки из `lucide-react`.  
> 
> **FORMAT:** Выведи готовый TypeScript файл `DocumentUploadZone.tsx` с JSDoc-комментариями и обработкой состояний ошибки валидации.

## Шаблон 2: Рефакторинг кода с улучшением

### Структура RTCF:
```markdown
### ROLE
Ты — Principal Software Engineer и эксперт по оптимизации производительности React и чистой архитектуре.

### TASK
Проведи глубокий рефакторинг следующего кода [НАЗВАНИЕ ФАЙЛА/ФУНКЦИИ]:
1. Устрани избыточные перерендеры и мемоизируй вычисления.
2. Улучши читаемость и раздели ответственность (Single Responsibility Principle).
3. Повысь типобезопасность (замени нестрогие типы на строгие интерфейсы и type guards).
4. Оптимизируй алгоритмическую сложность.

### CONTEXT
Исходный код:
```typescript
[ВСТАВИТЬ ИСХОДНЫЙ КОД]
```
Проблема: [ОПИСАНИЕ ТЕКУЩЕЙ ПРОБЛЕМЫ, НАПРИМЕР: ТОРМОЗИТ ПРИ СПИСКЕ ИЗ 1000 ЧАНКОВ]

### FORMAT
1. Анализ узких мест (3-4 пункта: что было не так и почему).
2. Обновленный чистый TypeScript код компонента/модуля целиком.
3. Оценка эффекта: как рефакторинг повлиял на производительность и сопровождаемость.
```

### Пример использования Шаблона 2:
> **Запрос к агенту:**
> 
> **ROLE:** Ты — Principal Software Engineer и эксперт по оптимизации React.  
> **TASK:** Проведи рефакторинг функции поиска по чанкам документов `searchLocalChunks`.  
> **CONTEXT:** Исходный код выполняет фильтрацию массива из 5000 чанков через тройной вложенный цикл `for` с регулярными выражениями без мемоизации, что вызывает фризы UI на 400мс при каждом вводе символа в поисковую строку.  
> **FORMAT:** Опиши проблемы текущей реализации, предоставь оптимизированную функцию с ранним выходом и мемоизацией, а также сравни сложность O(N) до и после.

## Шаблон 3: Написание тестов для существующего кода

### Структура RTCF:
```markdown
### ROLE
Ты — Senior QA Automation Engineer, специализирующийся на модульном и интеграционном тестировании TypeScript/React приложений (Vitest, React Testing Library).

### TASK
Напиши исчерпывающий набор автоматических тестов для модуля [НАЗВАНИЕ МОДУЛЯ].
Покрой следующие сценарии:
1. "Happy Path" (успешное выполнение с валидными данными);
2. Граничные случаи (пустые массивы, экстремальные значения, спецсимволы);
3. Сценарии обработки ошибок (невалидный ввод, сетевые сбои, тайм-ауты).

### CONTEXT
Код тестируемого модуля:
```typescript
[ВСТАВИТЬ КОД МОДУЛЯ]
```
Фреймворк: Vitest + @testing-library/react.

### FORMAT
1. Полный код тестового файла `[название].test.ts(x)` без пропусков.
2. Структура тестов с группировкой через `describe` и говорящими именами на русском языке в `it(...)`.
3. Мокирование внешних вызовов (vi.mock) при необходимости.
```

### Пример использования Шаблона 3:
> **Запрос к агенту:**
> 
> **ROLE:** Ты — Senior QA Automation Engineer (Vitest).  
> **TASK:** Напиши юнит-тесты для модуля семантического чанкинга `chunkEnterpriseDocument`.  
> **CONTEXT:** Модуль разбивает русский текст регламентов с перекрытием (overlap) и оценивает токены по формуле `length / 3.2`.  
> **FORMAT:** Файл `documentChunker.test.ts` с тестами: 1) корректное разделение длинного текста; 2) обработка пустой строки; 3) проверка перекрытия между соседними чанками; 4) сохранение метаданных документа в каждом чанке.

## Шаблон 4: Исправление ошибок и багов

### Структура RTCF:
```markdown
### ROLE
Ты — Senior Debugging Specialist и эксперт по отладке Fullstack-приложений.

### TASK
Локализуй и исправь ошибку в коде:
1. Определи точную первопричину бага (Root Cause Analysis).
2. Исправь код, устранив баг без регрессий в смежном функционале.
3. Добавь защитную проверку (defensive programming), чтобы баг не повторился.

### CONTEXT
Стек: TypeScript, React, Tailwind CSS.
Лог ошибки / Описание симптомов:
```text
[ВСТАВИТЬ ЛОГ КОНСОЛИ / ТРЕЙС ОШИБКИ]
```
Фрагмент кода, где возникает сбой:
```typescript
[ВСТАВИТЬ КОД]
```

### FORMAT
1. Причина сбоя: краткое техническое объяснение в 2-3 предложениях.
2. Исправленный код (полный блок или файл).
3. Рекомендация: как предотвратить подобные ошибки на уровне линтера или тестов.
```

### Пример использования Шаблона 4:
> **Запрос к агенту:**
> 
> **ROLE:** Ты — Senior Debugging Specialist.  
> **TASK:** Исправь ошибку отображения источников в компоненте `DocuChatResponse`.  
> **CONTEXT:** При передаче документа без поля `department` консоль падает с ошибкой `TypeError: Cannot read properties of undefined (reading 'department')` при рендеринге бейджа.  
> **FORMAT:** Объясни причину отсутствия опциональной цепочки, предоставь исправленный код компонента с безопасным доступом `chunk.metadata?.department ?? 'Общий отдел'` и обновленный интерфейс.

## Шаблон 5: Декомпозиция сложной задачи на подзадачи

### Структура RTCF:
```markdown
### ROLE
Ты — Lead Technical Product Manager и Solution Architect.

### TASK
Проведи техническую декомпозицию крупной эпик-задачи [НАЗВАНИЕ ЭПИКА]:
1. Разбей задачу на атомарные технические подзадачи (subtasks) для разработки.
2. Для каждой подзадачи укажи:
   - Стек и уровень (Frontend / Backend / Database / DevOps);
   - Критерии приемки (Definition of Done);
   - Потенциальные технические риски.
3. Выстрой подзадачи в строгой последовательности реализации с учетом зависимостей.

### CONTEXT
Проект: DocuMind AI (Enterprise RAG).
Требования: Обеспечение высокой скорости ответа (<1.5 сек), поддержка 152-ФЗ, ролевая модель доступа.
Описание крупной задачи: [ОПИСАНИЕ]

### FORMAT
1. Архитектурная диаграмма или поток данных (текстовая схема / Mermaid).
2. Нумерованный список подзадач в формате Markdown-таблицы:
   `| № | Подзадача | Слой | Зависимости | Сложность (S/M/L) | Критерий готовности |`
3. Оценка ключевых рисков и стратегия их минимизации.
```

### Пример использования Шаблона 5:
> **Запрос к агенту:**
> 
> **ROLE:** Ты — Solution Architect.  
> **TASK:** Декомпозируй внедрение модуля семантического векторного поиска документов с использованием PostgreSQL `pgvector` и модели эмбеддингов YandexGPT/DeepSeek.  
> **CONTEXT:** База содержит более 10 000 страниц регламентов. Нужно индексировать документы, генерировать векторы через фоновую очередь и отдавать топ-5 релевантных чанков за <200мс.  
> **FORMAT:** Выведи пошаговый план из 5 подзадач (DDL схемы БД -> фоновый воркер -> эндпоинт поиска -> UI-интеграция -> кэширование) со списком рисков.
