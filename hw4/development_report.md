## 1. Описание процесса разработки

Разработка клиентского приложения велась в строгом соответствии с Техническим заданием (ДЗ 3) и системными правилами `.cursorrules` (ДЗ 2). В качестве архитектурного каркаса выбрана **Концепция 2 («Enterprise Knowledge Workspace»)**, обеспечивающая эргономичное разделение на навигационный сайдбар департаментов, основной рабочий экран (чат с AI-ассистентом / реестр регламентов) и контекстные модальные окна.

### Этапы реализации:
1. **Инициализация проекта:** Настроен конфиг сборщика Vite, активирован строгий режим TypeScript (`strict: true`), интегрирован Tailwind CSS, подключены иконки Lucide React.
2. **Построение модульной архитектуры:**
   * `Sidebar.tsx` — боковая панель с динамическим подсчетом регламентов по департаментам и адаптивным выезжающим меню для мобильных экранов;
   * `ChatView.tsx` — диалоговый интерфейс со сносками на первоисточники, копированием ответов, анимацией загрузки (скелетон) и переключателем моделей (YandexGPT Pro, DeepSeek V3, Qwen 2.5);
   * `DocumentRegistryView.tsx` — каталог документов с многофакторной фильтрацией (поиск по тексту, фильтр по отделам, фильтр по грифу доступа `public`/`internal`/`confidential`);
   * `UploadModal.tsx` — модальное окно загрузки с двухуровневой клиентской валидацией форматов и размера файлов;
   * `SourceModal.tsx` — модалка детального просмотра цитируемой статьи нормативного документа.
3. **Автоматическое тестирование:** Написаны 3 тестовых набора Vitest, покрывающие ключевые бизнес-требования (RAG-поиск, RBAC/152-ФЗ, валидация файлов).

## 4. Описание возникших проблем и их решения

### Проблема 1: Переполнение интерфейса и срыв верстки на мобильных экранах (375px)
* **Симптом:** Шапка чата с переключателем моделей YandexGPT/DeepSeek не помещалась в ширину экрана смартфона и вызывала горизонтальный скролл страницы.
* **Решение с помощью AI:** Селектор моделей был обернут в `flex-wrap` с уменьшенными паддингами `px-2 py-1` на экранах `sm:`, а текстовые лейблы кнопок сокращены до компактных тегов.

### Проблема 2: Потеря фокуса и доступности при открытии модалок
* **Симптом:** При открытии модального окна загрузки скринридеры продолжали взаимодействовать с элементами основного реестра.
* **Решение с помощью AI:** Добавлен оверлей с блокировкой кликов `fixed inset-0 z-50`, клавиша `Escape` и явные ARIA-атрибуты для кнопок закрытия.
