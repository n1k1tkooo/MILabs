# Техническое задание (PRD): Корпоративная база знаний DocuMind AI (technical_specification.md)

**Продукт:** DocuMind AI (Enterprise Knowledge Base & On-premise RAG Assistant)  
**Версия документа:** 1.0 (MVP)  
**Соответствие регуляторам:** 152-ФЗ РФ «О персональных данных», режим коммерческой тайны  

---

## 1. Описание проекта
**DocuMind AI** — это веб-платформа для централизованного хранения нормативных документов предприятия (регламенты, приказы, инструкции) и предоставления сотрудникам контекстного диалогового AI-ассистента на базе технологий RAG (Retrieval-Augmented Generation). Система находит релевантные статьи документов по смыслу и формирует верифицированные ответы с указанием первоисточника, исключая передачу конфиденциальных сведений во внешние публичные сети.

---

## 2. Целевая аудитория и роли пользователей
1. **Линейные сотрудники (User):** Чтение общедоступных регламентов, быстрый диалоговый поиск ответов, просмотр цитируемых статей.
2. **Владельцы документов (Manager / HR):** Загрузка документов своих департаментов, редактирование метаданных, контроль версий.
3. **Офицеры безопасности и Администраторы (Security Officer / Admin):** Управление доступом (RBAC), просмотр документов с грифом `confidential`, аудит обращений к базе.

---

## 3. Функциональные требования (Functional Requirements)

### 3.1. Функция 1: Интеллектуальный диалоговый RAG-поиск с цитированием
* **FR-1.1:** Строка поиска должна поддерживать ввод запросов на естественном русском языке любой длины.
* **FR-1.2:** Система должна возвращать структурированный ответ в формате Markdown (списки, жирный шрифт для ключевых тезисов).
* **FR-1.3:** Под каждым ответом обязателен интерактивный аккордеон с перечнем использованных источников:
  * Номер источника, название документа, номер версии, департамент-владелец;
  * Точная цитата фрагмента регламента.
* **FR-1.4:** Поддержка переключателя AI-модели в интерфейсе:
  * `YandexGPT 5 Pro` (РФ, облако Yandex Cloud с соблюдением 152-ФЗ);
  * `DeepSeek-V3` (локальный On-premise инференс через vLLM / Ollama);
  * `Qwen-2.5-Coder` (локальный On-premise контур).
* **FR-1.5:** Защита от галлюцинаций: при отсутствии информации в базе ассистент обязан выдать стандартное системное сообщение об отсутствии сведений в регламентах.

### 3.2. Функция 2: Реестр документов и загрузка
* **FR-2.1:** Компонент реестра документов (`DocumentCard`) должен отображать: название, отдел, гриф доступа (`public`, `internal`, `confidential`), дату обновления, номер версии, количество страниц.
* **FR-2.2:** Модуль Drag-and-Drop загрузки (`DocumentUploadZone`) обязан принимать файлы `.pdf`, `.docx`, `.txt`, `.md` размером до 20 МБ.
* **FR-2.3:** Фоновая семантическая индексация: при загрузке документ очищается от служебных символов и разбивается на чанки по 800–1000 символов с перекрытием 150–200 символов по границам предложений.

### 3.3. Функция 3: Ролевая модель доступа (RBAC) и защита 152-ФЗ
* **FR-3.1:** При входе пользователя система считывает его роль и департамент из JWT-токена.
* **FR-3.2:** Алгоритм поиска обязан отсекать чанки документов уровня `confidential` для пользователей с ролями `user` и `manager` до момента генерации промпта для LLM.
* **FR-3.3:** Наличие визуального бейджа безопасности в шапке ответа:
  * Зеленый: `Общий регламент`;
  * Оранжевый: `Внутренний документ отдела`;
  * Красный: `Конфиденциально (152-ФЗ / КТ)`.

## 4. Нефункциональные требования (Non-Functional Requirements)

### 4.1. Производительность (Performance)
* **NFR-1.1:** Время первого рендера страницы (FCP) — не более 1.0 сек на десктопе.
* **NFR-1.2:** Время генерации ответа ассистента:
  * Через YandexGPT API — не более 2.5 сек;
  * Через локальный On-premise DeepSeek — не более 3.5 сек.
* **NFR-1.3:** Время векторного поиска топ-5 чанков в базе pgvector — не более 120 мс при базе до 50 000 чанков.

### 4.2. Безопасность и 152-ФЗ (Security & Compliance)
* **NFR-2.1:** 100% изоляция данных: запрет на отправку текста регламентов и запросов пользователей в неавторизованные публичные зарубежные API.
* **NFR-2.2:** Хранение токенов и ключей доступа в переменных окружения (`.env`), полное исключение секретов из клиентских бандлов.
* **NFR-2.3:** Защита от XSS и инъекций промптов (Prompt Injection / Jailbreak): очистка пользовательского ввода перед передачей в системный шаблон.
* **NFR-2.4:** Защита от CSRF и поддержка CORS со строгим белым списком разрешенных доменов компании.

### 4.3. Доступность и верстка (UX / UI / A11y)
* **NFR-3.1:** Адаптивная верстка (Mobile First) под разрешения 375px, 768px, 1024px, 1440px и 1920px.
* **NFR-3.2:** Доступность по стандарту WCAG 2.1 AA (контрастность текста не менее 4.5:1, поддержка навигации с клавиатуры, ARIA-атрибуты для интерактивных элементов).

## 5. Архитектура обработки ошибок (Error Handling Architecture)

| Код / Тип ошибки | Причина возникновения | Поведение системы | UX-решение для пользователя |
| :--- | :--- | :--- | :--- |
| **ERR_FILE_TOO_LARGE** | Пользователь загрузил файл > 20 МБ | Блокировка на клиенте до отправки в сеть | Красный баннер: «Файл превышает 20 МБ. Оптимизируйте размер документа» |
| **ERR_INVALID_FORMAT** | Формат файла не входит в белый список | Отклонение в `DocumentUploadZone` | Тост-ошибка с перечнем поддерживаемых типов (.pdf, .docx, .md, .txt) |
| **ERR_RBAC_FORBIDDEN** | Попытка запроса к документу с грифом `confidential` без прав | Фильтрация чанков в сервисе `accessControl` | Ассистент вежливо сообщает об отсутствии данных в доступных сотруднику регламентах |
| **ERR_LLM_TIMEOUT** | Время ответа модели превысило 8 сек | Прерывание запроса по AbortController | Автоматический fallback на резервный контур Yandex Cloud + кнопка «Повторить» |
| **ERR_EMPTY_KNOWLEDGE** | Сходство всех найденных чанков < 0.50 | Срабатывание правила защиты от галлюцинаций | «Информация в регламентах не найдена. Нажмите сюда, чтобы отправить вопрос в HR-отдел» |
| **ERR_AUTH_EXPIRED** | Истек срок действия JWT сессии | Перехват ошибки HTTP 401 в axios-интерцепторе | Всплывающее модальное окно быстрого входа без потери набранного текста вопроса |
